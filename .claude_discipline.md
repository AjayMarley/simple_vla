# Commit and PR Discipline

## Branch Strategy
- `main` is always green and never committed to directly.
- All work happens on feature branches, merged via PR.
- No branch merges until `cargo clippy --workspace -- -D warnings` is clean.

## Branch Naming
One branch per crate or cross-cutting concern, matching the build order:
```
feat/workspace-init
feat/hal-core
feat/ipc-zmq
feat/vision-subscriber
feat/integration-tests
```

## Commit Message Convention
Use [Conventional Commits](https://www.conventionalcommits.org/):
```
feat(hal): add JointCommand and 1kHz tick with atomic E-Stop
feat(ipc): add ZmqSubscriber with bounded crossbeam back-pressure
feat(vision): add zero-copy flatbuffer frame parser via zerocopy
fix(hal): enforce monotonic SafetyState escalation — no downgrade path
test(vision): add dimension-mismatch and alignment error cases
refactor(ipc): replace Box<[u8]> with Arc<[u8]> for zero-copy sharing
chore(workspace): pin flatbuffers to 23.5.26 across all members
```

Scope must match one of: `hal`, `ipc`, `vision`, `workspace`.

## PR Description Template
Each PR must include:

```
## What it does
<!-- One paragraph. What changed and what it enables. -->

## Why this approach
<!-- The reasoning behind key design decisions:
     - Why this data structure over the alternative?
     - Why this crate dependency?
     - What safety trade-off was made and why? -->

## Safety impact
<!-- None / Low / High.
     If High: describe the SafetyState transitions affected and
     the fail-state behaviour that was verified. -->

## How to test locally
<!-- Exact commands to verify the change: -->
cargo clippy --workspace -- -D warnings
cargo test --workspace
cargo build --release --workspace
<!-- Add any HAL-specific verification (e.g., allocation audit flags). -->
```

This is what a safety reviewer reads to understand your reasoning — not just what changed, but why it is safe.

## What to Avoid
- Squash-merging everything into a single commit — commit granularity is the audit trail.
- Force-pushing to `main`.
- PRs that span multiple crates — one crate boundary, one PR.
- Merging with any `clippy::unwrap_used` or `clippy::expect_used` warnings outstanding.
- Marking a PR "ready for review" before `cargo test --workspace` passes locally.
